A simulated week of card transactions streams past the same detection rules the project's Kafka detector runs. Each purchase is checked for bursts of rapid spending, amounts far above the card's normal, and purchases in two countries too far apart to travel between. The simulator plants fraud in the stream, so every alert can be checked against the truth.

How the full pipeline works

This page runs the highlighted box

Each purchase is keyed by card number, so all of a card's purchases land on the same Kafka partition, in order. That lets each detector replica keep per-card history in memory. Offsets are committed only after alerts are written (at-least-once), and malformed messages go to a dead-letter topic.

This page can't run Kafka: Vercel functions are short-lived, and Kafka needs an always-on broker and consumers. So the detector's rule engine (app/rules.py) runs here on a stream simulated for your visit. The full Kafka pipeline runs against real Apache Kafka in CI on every commit, and the build fails unless its alerts match this engine's alerts exactly.
